\begin{abstract}
This companion engineering white paper specifies the systems architecture, cryptographic wire protocol, multi-language implementation, threat model, and empirical simulation benchmark of \textsc{SecMesh-PQSI}~v2.1.0, complementing the Lean-verified mathematical foundations in White Paper~I.
Starting from a forensic security audit of legacy \code{BoogerCheeseOnRye/SecMesh@aff7dc6}, we replace all ten defective mathematical and network mechanisms with a layered \emph{Post-Quantum + Post-Super-Intelligence (PQ+PSI)} defense engine uniting a vendored MIT C11 \code{moonlab} cryptographic core (FIPS~202 SHA3/SHAKE, FIPS~197 AES-256, FIPS~203 ML-KEM-512/768/1024, SP~800-90B health tests, Toeplitz extraction, constant-time $\F_{2^{128}}$ Carter--Wegman IT-MAC, Mersenne $\F_{2^{61}-1}$ Byzantine Shamir sharing, QGTL entanglement/Chern--GHZ geometry, Ising expander contagion barriers, and Bravyi $[[144,12,12]]$ qLDPC verification), a Node.js~25 / OpenSSL~3.5.5 hybrid transport layer (X25519 + ML-KEM-768 + Ed25519 + ML-DSA-65 + SLH-DSA-128s + sequence-bound anti-replay CW-128 + OTP + threshold-hedged signing randomness), four live-executed Eshkol~v1.3.6 forward-mode dual-number automatic differentiation modules, and Rosette-Wire SHA-256 Merkle verifiable audit receipts.

We establish bit-exact cross-implementation FIPS~203 ML-KEM-768 interoperability between Tsotchke's C11 \code{moonlab} core and Node.js~25 OpenSSL~3.5.5 ($52/52$ C11 unit tests, $500/500$ fuzz inputs under ASan/UBSan, $15/15$ Node.js integration tests, $12/12$ Python pytest differential checks), measure a complete live lattice-hedged PQSI handshake ($25{,}007\text{ B}$ round-trip with canonical length-prefixed peer IDs), and report a pre-registered $30$-seed paired evaluation of the hardened mesh guardian health-field simulator (seeds \code{20260001}--\code{20260030}; exact permutation Holm--Bonferroni $p_{\mathrm{Holm}} = 3.73 \times 10^{-9}$ for both intrusion suppression and peak stress reduction).
We explicitly separate verified cryptographic interoperability from simulated mesh-defense telemetry and audit all $27$ public repositories across Tsotchke's GitHub namespaces honestly into integrated, optional-connector, and out-of-scope categories.
\end{abstract}

\section{Architectural Evolution: Legacy SecMesh v1 to SecMesh-PQSI v2}
\label{sec:arch}

Legacy \textsc{SecMesh}~v1 (\code{BoogerCheeseOnRye/SecMesh@aff7dc6})~\cite{secmesh_upstream} explored an ambitious vision---combining E91 Bell-inequality key auditing, hybrid post-quantum TLS, and adaptive mesh defense---but contained four critical systems-security vulnerabilities alongside the six mathematical defects proven in White Paper~I:
\begin{enumerate}[leftmargin=1.8em]
  \item \textbf{Cleartext secret key exposure on wire (\code{entangle-qkd.mjs:280}):} \code{runLink} serialized raw \code{bitA} and \code{bitB} arrays for \emph{all} rounds (including sifted key rounds) over raw unencrypted TCP JSON.
  \item \textbf{Unauthenticated control plane, wildcard CORS, and key leak (\code{entangle-peer.mjs}):} Bound \code{0.0.0.0} with \code{Access-Control-Allow-Origin: *}, exposed raw key material via \code{GET /e91}, and buffered TCP lines without a byte cap (unbounded OOM DoS).
  \item \textbf{Open UDP reflection/amplification echo (\code{mesh-guardian.mjs}):} Echoed arbitrary unauthenticated UDP datagrams back to spoofable source addresses.
  \item \textbf{Non-cryptographic \code{Math.random()} (\code{entangle-qkd.mjs}) and stale $S > 2$ threshold (\code{secsim-e91.mjs}):} Used V8's non-cryptographic PRNG for simulated basis choices and omitted finite-key margin checks in the interactive console.
\end{enumerate}

\textsc{SecMesh-PQSI}~v2 eliminates every single one of these defects through a four-layer zero-trust architecture:
\begin{itemize}[leftmargin=1.6em]
  \item \textbf{Layer 1 — Native C11 Moonlab Cryptographic Core (\code{native/}):} Vendors $18$ MIT-licensed C11 source files from \code{tsotchke/moonlab@cd3b234}~\cite{tsotchke_moonlab} compiled with \code{-std=c11 -D\_DEFAULT\_SOURCE -O2 -Wall -Wextra -Werror} ($0$ warnings, ASan/UBSan clean). Provides FIPS~202 SHA3/SHAKE, FIPS~197 AES-256, FIPS~203 ML-KEM-512/768/1024 with Fujisaki--Okamoto implicit rejection, NIST SP~800-90B health tests~\cite{nist_sp800_90b} (fail-closed on stuck-at faults), chunked OS CSPRNG seeding, constant-time $\F_{2^{128}}$ Carter--Wegman IT-MAC, XOR dual-survivability combiner, overflow-guarded Byzantine Shamir $(t,n)$ over Mersenne $\F_{2^{61}-1}$, QGTL/Chern--GHZ geometry, Ising expander contagion barriers, and thread-safe stack-allocated Bravyi $[[144,12,12]]$ BB qLDPC verification.
  \item \textbf{Layer 2 — Hardened Node.js~25 Hybrid Transport \& Guardian (\code{node/}):} Pairs Node~25 / OpenSSL~3.5.5 native \code{x25519}, \code{ml-kem-768}, \code{ed25519}, \code{ml-dsa-65}, and \code{slh-dsa-sha2-128s}~\cite{nist_fips203,nist_fips204,nist_fips205} with C11 Moonlab differential verification, canonical length-prefixed handshake framing, sequence-bound anti-replay Carter--Wegman $\F_{2^{128}}$ framing (per-frame fresh one-time pad discipline preventing two-frame key recovery, strict $64\text{ KiB}$ cap, loopback CORS, zero raw key material in \code{/status}, zero UDP echo), threshold-hedged signing randomness (\textbf{T6b}), and deterministic health-field defense telemetry.
  \item \textbf{Layer 3 — Executable Eshkol~v1.3.6 AD \& Rosette-Wire Receipts (\code{eshkol/}, \code{rosette/}):} Encodes four Eshkol~v1.3.6 S-expression AD modules (\code{finite\_key\_ad}, \code{qgt\_geodesic}, \code{bandwidth\_opt}, \code{chern\_ising\_ad})~\cite{tsotchke_eshkol} executed live by our portable forward-mode dual-number AD runtime (\code{eshkol-ad-runtime.mjs}) to $<10^{-12}$ analytical agreement, alongside canonical SHA-256 Rosette-Wire receipt bundles~\cite{tsotchke_rosette}.
  \item \textbf{Layer 4 — Six-Kernel Formal Proof \& Exact Audit Oracles (\code{lean/}, \code{python/}):} $27$ zero-Mathlib Lean~4.35.0 proofs (\textbf{T1a}--\textbf{T7b}) verified across all six distinct kernels via \code{lake comparator --paranoid}, plus $60$-digit Python exact-arithmetic differential oracles and automated README axiom drift checks.
\end{itemize}

\section{Hybrid PQ+PSI Handshake Protocol and Cross-Implementation Interop}
\label{sec:protocol}

\textsc{SecMesh-PQSI} implements a mutually authenticated hybrid handshake binding five cryptographic families into a single SHAKE-256 transcript digest and XOR dual-survivability key schedule:
\begin{align*}
  K_{\mathrm{PQ}} &= \mathrm{SHAKE256}\bigl(\text{\code{"SecMesh-PQSI-v2-KEM"}} \mathbin{\Vert} K_{\mathrm{X25519}} \mathbin{\Vert} K_{\mathrm{MLKEM768}} \mathbin{\Vert} \mathrm{ct} \mathbin{\Vert} \mathrm{ek} \mathbin{\Vert} H_{\mathrm{tx}}\bigr), \\
  K_{\mathrm{eff}} &= K_{\mathrm{PQ}} \oplus K_{\mathrm{IT}}, \qquad
  \mathrm{Tag} = \mathrm{CW128}_{r, s}\bigl(\mathrm{header} \mathbin{\Vert} \mathrm{payload}\bigr) \in \F_{2^{128}},
\end{align*}
where $K_{\mathrm{IT}}$ is drawn from a certified QRNG or pre-shared one-time pad (when operating in PSI mode; defaulting transparently to computational PQ-only mode when no physical/pre-shared pad is configured, without false PSI claims).

\subsection*{Cross-Implementation Bit-Exact FIPS~203 Interoperability}
To eliminate single-vendor coding or compiler bugs, our test harness (\code{test\_secmesh\_v2.mjs}) runs live bidirectional FIPS~203 ML-KEM-768 encapsulation and decapsulation between two independent implementations:
\begin{enumerate}[leftmargin=1.8em]
  \item Node.js~25 / OpenSSL~3.5.5 generates an ML-KEM-768 keypair $(\mathrm{ek}, \mathrm{dk})$ and exports raw $1{,}184$-byte $\mathrm{ek}$ (DER header stripped) plus a $32$-byte random seed $m$ to Tsotchke's C11 \code{secmesh\_core} binary.
  \item C11 \code{moonlab\_mlkem768\_encaps} validates $\mathrm{ek}$ (rejecting any coefficient $\ge 3329$), computes $(c, K_{\mathrm{C11}})$, and returns $(c, K_{\mathrm{C11}})$.
  \item OpenSSL~3.5.5 decapsulates $c$ using $\mathrm{dk}$ to recover $K_{\mathrm{OpenSSL}}$.
  \item \textbf{Observed result:} $K_{\mathrm{C11}} = K_{\mathrm{OpenSSL}}$ bit-for-bit across all $256$ bits, and single-bit ciphertext tampering triggers Fujisaki--Okamoto implicit rejection in both implementations.
\end{enumerate}

\begin{itemize}[leftmargin=1.6em]
  \item \textbf{Control (Unprotected baseline):} \code{defenders = 0}, firewall factor $\mathrm{fw} = 0.0$ (no active interception or healing, passive stress decay only).
  \item \textbf{Treatment (SecMesh-PQSI~v2 policy):} \code{defenders = 6}, $\mathrm{fw} = 0.7$ (authenticated admission gating, active defender interception $p_{\mathrm{kill}} = 0.35\,\mathrm{fw}$, and continuous self-stabilizing healing $p_{\mathrm{heal}} = 0.05\,\mathrm{fw}$ whenever $\mathrm{health}_i < 1.0$).
\end{itemize}
