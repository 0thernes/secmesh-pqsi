# Numbered Claims Ledger (`CLAIMS.md`)

Every technical and mathematical claim in `secmesh-pqsi v2.5.0` is tagged by its verification status. This ledger was corrected on 2026-11-26 to match an independent statement audit of commit `6c7f642` ([audit log](https://github.com/0thernes/0thernes-research-archive/blob/main/docs/reviews/2026-11-26-statement-audit.md)); see [`ERRATA.md`](ERRATA.md) for the errors that remain in the frozen paper and the formal code.

- `kernel-checked` — Proved in zero-Mathlib Lean 4.35.0 and replayed in 6 kernel runs (5 distinct implementations: the Lean kernel in paranoid and default mode, `lean4lean`, `nanoda`, `con-leche --verified`, `con-ron --verified`) via `lake comparator --paranoid` (`results/six_kernel_audit.txt`, CI run 45745957907). The tag applies only to the Lean statement as written, which is an integer, Boolean or polynomial fact.
- `paper-level` — An interpretation argued in the white paper (for example a quantum, probabilistic or protocol reading of a Lean statement). It is not formalized in Lean.
- `cited` — A known result from the literature, used but not proved here.
- `differential-tested` — Verified across independent C11, Node.js 25/OpenSSL 3.5.5, Eshkol AD runtime, and Python implementations.
- `numerical` — Verified via arbitrary-precision (60-digit `Decimal`) or seeded exact-arithmetic Python simulation.
- `open-problem` — Explicitly documented as an unresolved conjecture (not claimed solved).

All 28 Lean statements formalize known results or engineering arithmetic. None is claimed as new mathematics, and none is a bounded case of a Mega Atlas problem (archive class `FORMAL_INVARIANT_SUITE`).

## What Would Prove Us Wrong (Explicit Falsification Criteria — B42)

1. **Lean 4.35 Proof Soundness (`C1`–`C11`, Lean statements only):** Any counterexample to a Lean statement accepted by `Lean paranoid`, `lean4lean`, `nanoda`, `con-leche`, `con-ron`, or `Lean default`, OR any unpermitted axiom (`sorryAx`, `._native.*`, or custom `axiom`) appearing in `scripts/check_readme_axioms.py`, OR any vacuous hypothesis uninstantiable by `NonVacuity.lean`.
2. **FIPS 203 ML-KEM-768 Interop (`C12`):** Any valid NIST FIPS 203 public key `ek` and seed `m` where Moonlab C11 `moonlab_mlkem768_encaps` produces a shared secret differing from OpenSSL 3.5.5 `ml-kem-768` decapsulation, or where single-bit ciphertext tampering fails Fujisaki–Okamoto implicit rejection.
3. **Finite-Key v2, QGTL/Chern, Eshkol AD & Ising Differential Agreement (`C3`, `C8`, `C10`, `C12`):** Any parameter tuple where C11, Node.js 25, Eshkol AD runtime, and 60-digit Python `Decimal` disagree beyond `1e-11`, or where an adversary with $S \le 2.0$ receives `admitted = true` or `cert_bits > 0`.
4. **Hardened Guardian v2 Security (`C12`):** Any unauthenticated frame OR replayed sequence number accepted on the CW-128 control plane, any wildcard `CORS: *` header, any UDP echo amplification response, or any raw key bytes leaked via `/status`.
5. **Pre-Registered 30-Seed Benchmark (`C13`):** Failure to reproduce identical control/treatment means, bootstrap 95% CIs, and Holm–Bonferroni $p_{\mathrm{Holm}} = 3.73 \times 10^{-9}$ from seeds `20260001..20260030` in `exact_audit.py`.
